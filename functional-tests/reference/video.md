# Запись видео тестов

## Как это работает
- Тест сам читает пиксели вьюпортов (`FViewport::ReadPixels`) 30 раз в секунду и передаёт кадры в ffmpeg через pipe (`MPGridRecorder.h`). Рабочий стол не записывается, поэтому окна поверх игры не мешают и компьютером можно пользоваться.
- Функциональный тест: 1 ячейка 1920×1080 — его вьюпорт (с рендером там split-screen: игрок + боковой наблюдатель). Подпись — имя актора теста.
- Сетевой тест: сетка 2×2 по 960×540 — listen server и клиенты, подписи `P1 - listen server`, `P2 - client 1`…; `-MPPlayerGrid` раскладывает окна игроков (каждый в своём окне, включая сервер).
- **Правило: не меньше 30 кадров/с.** По умолчанию 30 (`-MPVideoFPS=N` поднимает до 60; меньше 30 задать нельзя), H.264. Если чтение кадров медленнее, кадр повторяется — видео идёт в реальном времени; сколько реально различных кадров получилось, пишет строка `Recording finished: … (N distinct frames per second)`. Меньше 30 различных — машина не успевала (много вьюпортов, нагрузка): предупреди или перезапиши.
- В кадр не попадает интерфейс, который рисует Slate поверх вьюпорта (подсказки, диалог, HUD).
- Нужен рендер: без него (`-nullrhi`) пикселей нет — запись не стартует.

## Команды
```powershell
# Записать, повторяя до зелёного прогона (максимум 3), сохранить видео зелёного:
powershell -ExecutionPolicy Bypass -File .claude/skills/functional-tests/scripts/run-tests.ps1 -Tests "Project.Network.TavernShift" -Video -UntilGreen 3
powershell -ExecutionPolicy Bypass -File .claude/skills/functional-tests/scripts/run-tests.ps1 -Tests "Project.Functional Tests.Tests.FTEST_GuestOrder" -Video -UntilGreen 3
```
- Видео — `A:\StealDrive\Saved\Videos\<Имя>_<дата-время>.mp4`; видео красного прогона переименовывается в `*_FAILED.mp4`.
- Вручную: ключи редактора `-MPRecordVideo=<файл.mp4 | папка> -MPFFmpeg=<путь к ffmpeg.exe>` (+ `-MPPlayerGrid` для сетевых).
- Если набор тестов: в папку пишется по файлу на тест.

## Проверить видео перед отправкой (обязательно)
```powershell
powershell -ExecutionPolicy Bypass -File .claude/skills/functional-tests/scripts/video-frames.ps1 -Video <mp4> -Count 4
```
Печатает длительность/размер/fps (код выхода 3, если меньше 30 fps — такое видео не отдавать) и сохраняет кадры (PNG) — **посмотри их** (Read): все ячейки живые (не чёрные, не одинаковые), подписи на месте, длительность ≈ время сценария. Для момента сбоя: `-At <секунды>`.

Отдать пользователю — путь к mp4 (или сам файл, если инструмент умеет прикладывать файлы), плюс одна строка: что за прогон, результат, длительность.

## Подводные камни
- Не записывай рабочий стол (gdigrab): любое окно поверх игры попадёт в кадр (так уже записалось окно Claude вместо игры).
- Старт полного редактора иногда падает на CEF-assert — `run-tests.ps1` повторяет запуск сам.
- 4 отрисованных вьюпорта + запись нагружают машину: игра идёт медленнее, таймауты сценария рассчитаны с запасом, но сетевую смену с видео при сомнении прогоняй с `-UntilGreen`.
- Не удаляй чужие видео; свои неудачные — можно, сообщив.
