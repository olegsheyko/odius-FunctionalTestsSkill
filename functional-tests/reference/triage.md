# Проверка и исправление: как разбирать красный тест

## Цикл

1. **Прогон** `scripts/run-tests.ps1 -Tests <фильтр> [-Count N]` → он сам печатает сводку `summarize-log.ps1`: результат, `[game]/[timeout]/[setup]`, последние шаги упавшего игрока, неожиданные ошибки лога, обходы, отчёты, смену, брошенные дела.
2. **Классифицируй** (ниже). Не исправляй, пока не понял, кто виноват.
3. **Воспроизведи**: тот же сид `-Seed N` (сид в `Run report: seed N`). Если не воспроизводится — гонка/физика: смотри серию, а не один прогон.
4. **Добавь диагностику, если причина неясна** — не гадай. Положи увиденное в `StepNote` (что трасса попала, где игрок, что впереди — sweep капсулой), выведи состояние станции, перепрогони. Пример: «stopped short by BP_Fermenter_C_0.VesselWall_06» сразу показал, что бот шёл в борт.
5. **Исправь причину**, а не симптом. Перепрогони серией (≥3–4) + остальные тесты, если трогал базу.
6. Посмотри видео/кадры, если поведение «странное» (`-Video`, `scripts/video-frames.ps1`).

## Кто виноват

| Признак | Виновник | Что делать |
|---|---|---|
| `[setup]`: нет ассета/компонента/поля | Тест устарел (игру поменяли) | Сверь с кодом/`dump-assets`, обнови тест |
| Игра поменяла механику намеренно (новый CL: «ЛКМ вместо E», «сбрасывать в горловину») | Тест устарел | Узнай, как теперь задумано (GDD, код, автор CL), перепиши шаги; спроси, если способов несколько |
| Игра нарушает свои же правила / GDD (кружка в игроке, отзыв не тот, предмет проваливается) | Баг игры | Тест оставь честным (красным), опиши баг: файл:строка, сид, лог, предложение. Чинить игровой код — только с согласия |
| Механика работает, но бот не дошёл/не попал/застрял | Бот (тест) | Исправь шаг так, как поступил бы человек: обойти, подождать, повторить, подойти с другой стороны |
| Гонка между игроками (взял один — второй ждёт вечно) | Бот (координация) | Проверка «ещё актуально?» перед действием, захват на доске, `AbandonTask` |
| Строка Warning/Error в логе, не связанная со сценарием | Шум (контент/движок) | В `IgnoredLogErrors` / `ExpectKnownNoise` с комментарием «что, где баг, когда убрать». Это тоже находка — сообщи |
| Крэш редактора `BUseSupportedRHIRenderer` (CEF) на старте | Окружение | Перезапуск (скрипт делает сам); сетевые/рендер — только полный редактор |
| Сборка не линкуется | Открыт редактор / идёт тест | Закрой; `build.ps1` проверяет |

**Нельзя**: двигать игрока или предметы кодом (телепорт), спавнить что-либо, чтобы обойти препятствие (ингредиенты рядом, стол, навмеш), ослаблять проверку, чтобы позеленело (заменить `==` на «что-нибудь»), увеличивать таймаут без понимания, глушить в игноре ошибку, которая относится к сценарию, «помогать» игре прямым вызовом метода. Если по-честному не получается — тест остаётся красным, а в отчёте — почему.

## Частые симптомы → причина → исправление

| Симптом (что в логе) | Причина | Исправление |
|---|---|---|
| `… timed out …: interaction trace hits BP_FirstPersonCharacter_C_N` | На линии взгляда напарник | `AddClickOn` (обходит); иначе другая точка подхода |
| `… trace hits StaticMeshActor_… ` и Z цели ниже пола / огромное расстояние | Предмет провалился сквозь пол (клиентская физика) | Пропускать такие (`IsSunkIntoLevel`, Z ниже станции на 500), выбрать другой; это находка для команды |
| `clicked on … nothing happened` | Игра отказала по правилу (котёл не берёт дрова при готовом сусле; руки заняты; не та зона) | Найди условие отказа в C++ (`return false` в начале функции) и проверяй его до/во время действия |
| `waiting for the station to be ready (e.g. the lid to open)` | Крышка открывается только для игрока в зоне загрузки и только пока ферментеру нужно сусло | Ограничить число носильщиков местом; если не в зоне >5 с — заново от низа лестницы |
| `Stuck at … blocked by BP_Fuel_C_… / BP_Potion…` | Предмет лежит в проходе | Класть вещи на открытые места вне маршрутов (`OpenSpotNear`) |
| `Stuck at …` у киоска / `waiting for … in the way` | Очередь гостей / стоящий игрок | Ожидание + обход (`AddNavGoTo` делает); свободные игроки отходят (`RestSpot`) |
| `… cannot be reached: walked straight at it … not visible` | Цель за стойкой/стеной | Точка подхода с `MustSee`; для лестниц — по оси подхода, не «ближайшая по пути» |
| `Step 'Look for work' timed out` | Никто не может взять дело (условие никогда не выполнится) | Проверь `PickTask`: условие ждёт состояния, которое не наступит (например, ферментер занят другим пивом) |
| `E at the tap (pressed N times) gave no wort` | Серверная трасса попала в напарника у крана; или руки не пусты | Повторное E (есть); проверь руки |
| Тест красный только с рендером | Шум рендера, компиляция меша, движение курсора, медленнее кадры | Игнор шума с комментарием; ждать компиляции; таймауты |
| Тест красный только headless | Нет курсора/UI (помешивание, диалог) | Обход через `NoteShortcut` — и честно в отчёте |
| Прогоны «то зелёный, то красный» | Гонка, физика, сеть | Серия + сиды + диагностика; исправлять причину, не повторами |
| `Condition failed` дважды на кадре 0 | Старт редактора, не тесты | Игнорировать |
| Не может войти в помещение / выйти из него / залезть по лестнице | Нет пути по навмешу (дверь, лестница не покрыты), путь ведёт в стену | Честно: `PathThroughDoorway`, `FindStairsUpTo` + `AddClimbTo`, другая точка подхода. Не помогло за 2 попытки — **стоп**: опиши, где разрыв (координаты, кадр), спроси пользователя. Телепорт внутрь — запрещено |
| На экране `NAVMESH NEEDS TO BE REBUILT`, пути нет | Навмеш карты устарел / не сохранён — проблема контента | **Стоп**, сообщи (карта, кадр). Не строить навмеш в тесте |
| Не подбирает предмет с пола / со стола | Прицел не на предмете (под прицелом другое), предмет за краем дальности, руки заняты, предмет провалился | `DescribeInteractionTrace` в `StepNote`, `AddClickOn` (прицел + повтор), подойти ближе; разобраться, что под прицелом. Создать стол/новый предмет — запрещено |
| Ресурса нет там, где бот может его взять | Зона ресурсов вне навмеша / пуста | **Стоп** и вопрос пользователю (это находка про карту). Спавнить ресурс рядом — запрещено |

## Диагностика — полезные приёмы

- `StepNote = FString::Printf(...)` в шаге — попадёт в сообщение таймаута.
- `DescribeInteractionTrace(Target)` — что сейчас под прицелом и на каком расстоянии.
- Sweep капсулой вперёд (`SweepSingleByChannel(ECC_Pawn, MakeCapsule(...))`) — кто/что преграждает путь.
- `ReportStep("[lane] ...")` — строка в лог по ходу (например, «off the fermenter stairs, climbing again»).
- Состояние станции строкой: `CauldronState()`, `TavernSnapshot(World)` в сетевых.
- Шаги конкретного игрока: `summarize-log.ps1 -Log <log> -Lane P3_Client2 -Steps 40`.
- Кадры видео в момент сбоя: `video-frames.ps1 -Video <mp4> -At <сек>` (время от начала записи ≈ время сценария).

## Когда остановиться и спросить пользователя

- Нашёл баг игры, исправление — в игровом коде/ассете.
- Механика изменилась, и неясно, какой способ игры теперь задуман.
- Чтобы позеленеть, нужно поменять правила проверки (что считать успехом).
